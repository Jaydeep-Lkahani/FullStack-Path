Almost every real application loads data from a server. In the browser the standard tool is **`fetch`**: a promise-based API for HTTP requests. Combined with what you learned about HTTP and `async/await`, it's the bridge between your UI and your backend.

## Your first request

```js
const response = await fetch("https://jsonplaceholder.typicode.com/todos/1");
const todo = await response.json();
console.log(todo);   // { userId: 1, id: 1, title: "delectus aut autem", completed: false }
```

Two awaits: the first resolves when the **headers** arrive (a `Response` object), the second reads and parses the **body**.

### The Response object

```js
response.ok;          // true if status is 200–299
response.status;      // 200
response.statusText;  // "OK"
response.headers.get("content-type");   // "application/json; charset=utf-8"
response.url;         // final URL (after redirects)

await response.json();   // parse as JSON
await response.text();   // plain text / HTML
await response.blob();   // binary: images, files
await response.formData();
```

A body can be consumed **once**. To read it twice, `response.clone()` first.

## Error handling: fetch does not reject on 404

This catches almost every beginner:

```js
const res = await fetch("/api/does-not-exist");
console.log(res.status);   // 404 — but NO exception was thrown!
```

`fetch` only rejects (throws) on **network failures** (offline, DNS error, CORS block, aborted). HTTP errors like 404 and 500 are *successful* fetches that returned an error response. You must check:

```js
async function getJson(url, options) {
  const res = await fetch(url, options);
  if (!res.ok) {
    // many APIs return a JSON error body — try to include it
    const detail = await res.text().catch(() => "");
    throw new Error(`HTTP ${res.status} ${res.statusText}: ${detail}`);
  }
  return res.json();
}
```

Wrap this tiny helper once and reuse it everywhere. (Libraries like Axios throw on non-2xx by default; with `fetch` it's your job.)

## Sending data

### GET with query parameters

```js
const params = new URLSearchParams({ q: "javascript", page: 2 });
const res = await fetch(`/api/search?${params}`);   // /api/search?q=javascript&page=2
```

`URLSearchParams` handles encoding for you (spaces, `&`, unicode), so never build query strings by hand.

### POST JSON

```js
const res = await fetch("/api/todos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Learn fetch", completed: false }),
});
const created = await res.json();   // typically 201 Created with the new record
```

### Other methods

```js
await fetch(`/api/todos/${id}`, { method: "PATCH", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ completed: true }) });
await fetch(`/api/todos/${id}`, { method: "DELETE" });   // 204 No Content → no body to parse
```

### Forms and files

```js
const formData = new FormData(formElement);
formData.append("avatar", fileInput.files[0]);
await fetch("/api/profile", { method: "POST", body: formData });
// Do NOT set Content-Type yourself — the browser adds the multipart boundary.
```

### Authentication

```js
fetch("/api/me", { headers: { Authorization: `Bearer ${token}` } });   // token-based
fetch("/api/me", { credentials: "include" });                           // send cookies cross-origin
```

Same-origin requests send cookies by default; cross-origin ones don't unless you set `credentials` (and the server allows it). Never put secrets in client-side code — anything in the browser is visible to the user.

## Cancellation and timeouts

```js
const controller = new AbortController();
const promise = fetch("/api/slow", { signal: controller.signal });

controller.abort();        // the promise rejects with AbortError

// Built-in timeout helper
const res = await fetch("/api/slow", { signal: AbortSignal.timeout(5000) });
```

This is also how you avoid **race conditions** in search-as-you-type: abort the previous request when a new one starts, so a slow old response can't overwrite a newer one.

```js
let controller;
async function search(query) {
  controller?.abort();
  controller = new AbortController();
  try {
    const data = await getJson(`/api/search?q=${encodeURIComponent(query)}`, { signal: controller.signal });
    renderResults(data);
  } catch (error) {
    if (error.name !== "AbortError") showError(error);
  }
}
```

## CORS

Browsers enforce the **same-origin policy**: a page at `https://app.com` can't read responses from `https://api.other.com` unless that server opts in via **CORS** (Cross-Origin Resource Sharing) headers.

```text
Access-Control-Allow-Origin: https://app.com
Access-Control-Allow-Methods: GET, POST, PUT, DELETE
Access-Control-Allow-Headers: Content-Type, Authorization
```

- For "non-simple" requests (JSON POST, custom headers) the browser first sends an **OPTIONS preflight** and only proceeds if the server's answer allows it.
- A CORS error appears in the console, and `fetch` rejects with a `TypeError: Failed to fetch`. The **server** must be fixed — you can't work around it from client code. (In development, a proxy or the Next.js/Express `cors` middleware does the trick.)
- CORS protects *users*, not your server: `curl` and other servers ignore it, so it is not a substitute for authentication.

## A complete example: render fetched data

```html
<ul id="posts"></ul>
<p id="status" aria-live="polite"></p>
```

```js
const list = document.querySelector("#posts");
const status = document.querySelector("#status");

async function loadPosts() {
  status.textContent = "Loading…";
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/posts?_limit=5");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const posts = await res.json();

    if (posts.length === 0) {
      status.textContent = "No posts yet.";
      return;
    }

    list.replaceChildren(
      ...posts.map((post) => {
        const li = document.createElement("li");
        li.textContent = post.title;      // textContent: safe against XSS
        return li;
      }),
    );
    status.textContent = "";
  } catch (error) {
    status.textContent = `Something went wrong: ${error.message}`;
  }
}

loadPosts();
```

Always design for the **four states** of remote data: **loading**, **error**, **empty**, and **success**. Skipping them is the most common difference between demo code and production code. You will formalise this with TanStack Query in the React module.

## Other things worth knowing

- **JSON** helpers: `JSON.stringify(obj, null, 2)` pretty-prints; `JSON.parse(text)` throws on invalid JSON. `JSON.stringify` drops `undefined`, functions and symbols, and turns `Date` into strings.
- **Caching**: `fetch(url, { cache: "no-store" })` bypasses the HTTP cache; browsers otherwise follow the response's `Cache-Control` headers.
- **Streaming**: `response.body` is a `ReadableStream`, which lets you process large downloads or streamed AI responses chunk by chunk.
- **Node.js** (v18+) has the same global `fetch`, so the code in this lesson works on servers too.
- Older code uses `XMLHttpRequest` or the Axios library; you'll see both, but `fetch` is the standard.

POST a new post to `https://jsonplaceholder.typicode.com/posts` with a title and body from a form, then display the returned `id`. Disable the submit button while the request is in flight.

<Solution>
```js
form.addEventListener("submit", async (e) => {
  e.preventDefault();
  const button = form.querySelector("button");
  button.disabled = true;
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/posts", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(Object.fromEntries(new FormData(form))),
    });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const created = await res.json();
    output.textContent = `Created post #${created.id}`;
    form.reset();
  } catch (err) {
    output.textContent = `Error: ${err.message}`;
  } finally {
    button.disabled = false;
  }
});
```

<Exercise title="Debounced search with cancellation">
Build a search input that queries `https://jsonplaceholder.typicode.com/posts?q=<text>` 300ms after the user stops typing and cancels the previous in-flight request. Why is cancellation needed?

<Solution>
```js
let timer;
let controller;
input.addEventListener("input", () => {
  clearTimeout(timer);
  timer = setTimeout(async () => {
    controller?.abort();
    controller = new AbortController();
    try {
      const res = await fetch(
        `https://jsonplaceholder.typicode.com/posts?q=${encodeURIComponent(input.value)}`,
        { signal: controller.signal },
      );
      render(await res.json());
    } catch (e) {
      if (e.name !== "AbortError") showError(e);
    }
  }, 300);
});
```
Without cancellation, responses can arrive out of order: a slow response for "ja" could overwrite the results for "javascript", showing stale data.
</Solution>
